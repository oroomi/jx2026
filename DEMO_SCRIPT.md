## Hard questions with answer slots

**1. Who exactly is it for?**
Answer: the accelerator lead (A'Pelago screens many applications for a small cohort; the exact numbers are theirs to state, we do not claim them) and the VC associate (Redstone Blue, pre-seed and seed). Monday decision: which five do I call this week, and about what.

**2. What was built this weekend versus pre-existing?**
Answer: see DISCLOSURE.md. Short version: "All application code in this repository was written between 16 Oct 18:00 and 18 Oct 10:00 (Helsinki) with AI coding tools. We brought our own build tooling, checklists, and the public datasets listed there, and we used the third-party services listed there." No hedging.

**3. What breaks first at scale?**
Answer: request-time computation. Every page computes the feed rule from the whole store on each request; with wide intake and the Nordic registers the store grows many times over, so the feed and the backtest must be computed once per refresh instead. The home list and the matchmaking index are already cached and warmed at start. ARCHITECTURE.md names it. Name it before they do.

**4. Did the wide intake find your startups early?**
Answer: the pitch line above, word for word. If pressed on the other 3: "Finnish Sauna Shop, Sub Marine Store and Taikoa are registered as retail, wholesale and consulting, outside the intake's code families, and 12 of the 19 are outside the Finnish register. Your real entry dates would replace our January 2026 reference; that is the one ask in PILOT.md."

**5. Is the ocean impact level a real impact score?**
Answer: no, and the page says so. It is evidence readiness: how well an impact area is evidenced in public records, on nine rungs that each name the record that must be on file. The Ocean Impact Navigator publishes areas and KPIs but no levels, so the ladder is ours and is open for you to change (PILOT.md, weeks 5 and 6).

**6. Where is the score in the matching?**
Answer: there is no total score for a startup, by rule (A34). The pages print no number, but the API carries internal ordering values and you should say so if asked: `/api/match/*` returns an ordinal `rank` and a `weight` on each reason, and `/api/company/{key}` returns the declared research dataset's own match `score` and its readiness numbers (`oi_score`, `br_score`, `ir_score`, `oir_score`). Every counterpart shows the reasons that hold, each with its record, and the ones that did not hold with a note. The weights only order the list, and they are a stated hypothesis: there is no ground truth for who should have met whom, so a partner rating of 20 pairs is the first real check (PILOT.md). On a startup's Match page the visitor can weigh the reasons (D90): seven sliders from the owner's brief, six of them mapped to the matcher's reasons, and the list reorders in the browser. Ticket size is disabled, because a startup's funding ask is not in public records. The weights are the visitor's, and the page still shows no total.

**7. Is there an AI model behind Aava and the Ask Aava bar?**
Answer: yes, behind the demo flag, since 17:37 UTC on 17 Oct, and nowhere else. Without the flag the pages, the memo, the matching and the bar's answers are built from records by code (a deterministic router); the voice is a recording made at build time (ElevenLabs) where the text still matches, or the browser's own voice. With the flag, a typed or spoken question goes to Aava on Claude Sonnet 5.5 through the Messages API, with read-only tools over this site's own records (no SQL, no writes, no network), adaptive thinking at low effort and at most 3 steps. Measured: five real selftests took 4.7 to 7.0 s and cost $0.015 to $0.026 a turn. Code checks every company name and link in the answer against what the tools returned and prints a Sources line; it falls back to the deterministic answer on any failure; it is rate-limited (8 turns a minute per address, 400 a day). Say the limit if asked: code checks names, links and addresses, not that every figure in a sentence matches the record it restates. Elsewhere the only AI in the data path is the stitcher, whose proposals plain code checks twice, and the company summaries, whose every sentence code verifies.
